# Decisions

One line per call that was not obvious.

- 2026-11-05 · The repository was cleared and regenerated from the kit template (kit v0.2.1, the latest tag) as the owner asked; the old Marqueue code (playbill, Scoutline) stays in git history.
- 2026-11-05 · `main` did not exist (the default branch was a session branch); it was made from that branch so the first pull request has a base, and is the branch releases run on.
- 2026-11-05 · Releases are held until v0.1.0: `docs/RELEASE_HOLD` makes the release workflow skip, because the owner wants v0.1.0 only when movies, TV, downloads and TRaSH defaults work end to end. The rule "every merge ships a release" applies from v0.1.0 on.
- 2026-11-05 · The template's desktop app is kept (the kit's proof app, free CI coverage); the Android app is added in its own step at the end, as the owner ordered.
- 2026-11-05 · Prowlarr still adds Marquee as Sonarr and Radarr (goal 2, the API stays compatible), but Marquee keeps no indexers of its own: indexers Prowlarr pushes are accepted and handed to Lantern, or answered as an empty list, decided in the downloads step.
- 2026-11-05 · The template's .gitignore only ignores /target, but each of server/, web/ and desktop/ is its own workspace with its own target/; Marquee ignores target/ everywhere. To fix in the kit (not in this session's reach).
- 2026-11-05 · License GPL-3.0-only as the owner asked (the kit's MIT code it depends on is compatible). The original apps are reference only; data files (TRaSH Guides, indexer YAML definitions) are reused as they are and credited in README.md.
- 2026-11-05 · The jfa-go replacement goes in the Plex/Jellyfin step (it needs the Jellyfin and Plex connections) and its import in the migration step. Marquee never stores a plain password: it sets the Jellyfin password at the moment the person sets or resets it in Marquee.
- 2026-11-05 · Anime gets its own step after TRaSH (it builds on TV, downloads and the TRaSH sync) and is not part of v0.1.0, which the owner defined as movies, TV, downloads and TRaSH. The TV model carries a media type from the start so anime series reuse it.
- 2026-11-05 · Roles are stored as `owner`, `admin`, `requester` and `viewer`; the template's `user` becomes `requester`. Quotas are per account (0 = no limit, a period in days) with defaults for new accounts in Settings → General.
- 2026-11-05 · Root folders are one shared table with a kind (`movie`, `tv`, `anime`), so the Radarr and Sonarr APIs each answer with their own kind and one disk check covers all.
- 2026-11-05 · Settings → Connections holds only the Lantern address and key and the TMDB key; no download client or indexer settings exist (downloads go through Lantern).
- 2026-11-05 · The Radarr API is served under `/radarr` (base URL `http://marquee:8080/radarr`) and the Sonarr API will be under `/sonarr`: both apps answer `/api/v3/queue`, `/calendar` and more with different things, and every client (Prowlarr, Seerr, Homepage, nzb360, LunaSea) takes a base URL with a path.
- 2026-11-05 · `system/status` answers `appName: Radarr` and Radarr's version (6.4.4) so clients' version checks pass; Marquee's own version is in `packageVersion`.
- 2026-11-05 · Contract tests compare Marquee's answers with real Radarr 6.4.4 answers recorded from the linuxserver image (TMDB was out of reach, so the movies were put into Radarr's database directly; the answers are Radarr's own serialisation).
- 2026-11-05 · The starter movie quality profiles and the quality list are Radarr's defaults (data files), so existing tools find what they expect; the TRaSH step makes TRaSH's profiles the default.
- 2026-11-05 · Indexers Prowlarr pushes are kept (secrets masked as Radarr does) and not used for searching: downloads go through Lantern. The downloads step decides whether they are handed to Lantern.
- 2026-11-05 · `DELETE movie?deleteFiles=true` forgets the movie but never deletes media files for now; deleting files needs the files step and stays an explicit choice.
- 2026-11-05 · When TMDB can't be asked (no key or unreachable), a Radarr-API add keeps the details the caller sent, so Seerr and migrations still work; the next refresh fills in the rest.
- 2026-11-05 · The server makes its API key on the first start (Settings → General) because Prowlarr and Seerr need one.
- 2026-11-05 · TV information comes from TMDB too (one key for movies and TV); TheTVDB ids come from TMDB's external ids, so Sonarr clients that send `tvdbId` still work. TheTVDB's own API needs a paid key.
- 2026-11-05 · TMDB has air dates but no air times, so `airDateUtc` is midnight UTC of the air date; Sonarr uses the network's local time. An episode counts as aired from that moment.
- 2026-11-05 · Movies and TV share one quality table and one profile table, so the ids Marquee's Sonarr API gives are its own (Sonarr numbers from 1); clients read the ids from the lists and don't depend on the numbers.
- 2026-11-05 · The Radarr and Sonarr APIs share one piece of code for the parts that are the same in both (queue, history, profiles, root folders, tags, indexers, commands); only movie and series parts differ.
- 2026-11-05 · Specials (season 0) are never monitored by themselves, like Sonarr.
- 2026-11-05 · Lantern's download hub isn't built yet, so Marquee writes the hub contract (docs/LANTERN_HUB.md) and is tested against a stand-in; searching already uses Lantern's real Prowlarr API (`/api/v1/search`).
- 2026-11-05 · Marquee asks Lantern about downloads every minute and also takes Lantern's callbacks, so downloads finish even when Lantern can't reach Marquee (no address set, or another network).
- 2026-11-05 · Release names are read by Marquee's own parser (quality, season and episodes, absolute numbers, group, proper/repack), with Sonarr's quality names; movies use Radarr's spelling of the two remux qualities.
- 2026-11-05 · A release must match the title (articles and marks ignored) and the year within one; a season pack is taken only when every aired episode of the season is wanted.
- 2026-11-05 · A file that is replaced by a better one is moved to `<root folder>/.marquee-recycle/`, never deleted; emptying it stays the owner's choice.
- 2026-11-05 · Adding a movie or series through the Radarr or Sonarr API searches at once only when the caller asks (`searchForMovie`, `searchForMissingEpisodes`), like Radarr and Sonarr.
- 2026-11-05 · TRaSH data comes in as a built-in snapshot of TRaSH's JSON files (`server/data/trash/bundle.json`, made by `cargo run --example trash_bundle`), so the first start needs no network. The sync asks GitHub for the newest commit and its file list (two API calls) and fetches only files whose git blob id changed.
- 2026-11-05 · First-start defaults: HD Bluray + WEB for movies, WEB-1080p for TV, [Anime] Remux-1080p for anime (and for anime movies), Jellyfin naming; TRaSH's "default" custom format groups for each profile are included. The starter Radarr/Sonarr profiles are removed then, but only the ones nobody changed and nothing uses.
- 2026-11-05 · "Never overwrite your edits": each TRaSH item keeps a fingerprint of what Marquee last wrote. A TRaSH change goes in by itself only when the item still matches; otherwise it waits on the Quality page for "Use TRaSH's" or "Keep mine". A deleted item stays deleted. Sizes still at Radarr's/Sonarr's stock values count as unedited.
- 2026-11-05 · Profiles list only their own custom formats in `formatItems` (Radarr lists every format with 0), so a format someone adds doesn't make every TRaSH profile look edited.
- 2026-11-05 · Custom formats match like Radarr/Sonarr (grouped by condition type, required and negate). TRaSH's .NET expressions run on fancy-regex; a `[` inside a class is escaped, and the variable-length look-behinds TRaSH uses (always at the start of an alternative) are checked against the text before each match. Indexer-flag conditions never match (Lantern doesn't pass flags). The original language counts as Japanese for anime and English otherwise, until Marquee keeps each title's language.
- 2026-11-05 · Anime has its own quality list (a copy of TV's) so TRaSH's anime sizes don't change TV's; anime custom formats are Sonarr's and shared with TV, as in Sonarr.
- 2026-11-05 · The Radarr and Sonarr `customformat` endpoints only list formats for now (what Prowlarr, Homepage, nzb360 and LunaSea read); adding or changing formats goes through Marquee's TRaSH page, not Recyclarr-style API writes.
- 2026-11-05 · `MARQUEE_TRASH_AUTO=false` turns off the first-start setup and the schedule (the integration tests set it); the TRaSH page still works by hand.
- 2026-11-05 · The Seerr API is served at `/api/v1` with no prefix, because Seerr has no URL base and clients (LunaSea, nzb360, Homepage) add `/api/v1` themselves; Marquee's own API has no `/api/v1` paths. The web app's request pages use the same API.
- 2026-11-05 · Seerr's `status` answers version 2.7.3 (the Jellyseerr version the contract tests were recorded from) so clients' version checks pass; Marquee's version is in `commitTag`.
- 2026-11-05 · Seerr contract answers were recorded from Jellyseerr 2.7.3 (`fallenbagel/jellyseerr`; the `seerr-team` image couldn't be pulled here) with requests put into its database directly, since TMDB was out of reach. Discover, search and details follow Seerr's API spec instead (TMDB's names in camelCase).
- 2026-11-05 · Seerr's API key acts as the owner, and `X-Api-User: <id>` as that account, like Seerr. Seerr's own sign-in (`/auth/local`, Plex, Jellyfin) is not answered: tools use the API key, and media-server sign-in belongs to the media servers track.
- 2026-11-05 · Roles map to Seerr's permission bits: owner and admin are ADMIN, can-request is REQUEST plus AUTO_APPROVE_MOVIE/TV when set, read-only is none. Setting permissions through the Seerr API maps the bits back to a role.
- 2026-11-05 · A title's availability is worked out from the library each time (files there or not, per season for TV), never stored; an admin can still set it by hand (`POST /media/{id}/{status}`). Seasons with nothing aired yet don't count against "available".
- 2026-11-05 · Limits count requests that still stand (not declined, not failed) made in the period; TV counts seasons, like Seerr. Admins have no limit.
- 2026-11-05 · Approving puts the title into the library with the request's profile and folder (else the defaults) and starts a search; when that can't be done (no folder, TMDB down) the request is marked "Didn't work" with the reason and Retry tries again, instead of answering an error.
- 2026-11-05 · Anime is Japanese animation by TMDB (genre Animation, language ja), or a series already of kind anime. Its requests keep the language choice (account default, changeable per request); the anime step uses it for the track check. AniList is asked only for the request page's season list.
- 2026-11-05 · Request news goes to Discord and ntfy now. Email waits for `crate::mail` (media servers track). Web push needs a service worker and VAPID keys in the kit's web app, so it belongs in the kit and comes in its own change.
- 2026-11-05 · Anime preferences (dub, dual or sub, dub language, subtitle language) live in their own `anime_prefs` table keyed by user, so core doesn't edit `users.rs`, which the media servers track owns.
- 2026-11-05 · Anime ids come from Fribb's anime-lists (`anime-list-full.json`), refreshed daily; set the list address to `off` to stop it. AniList is read through its public GraphQL API; tests use a local stand-in.
- 2026-11-05 · When a file's real tracks don't match the requested audio, Marquee searches again by default (`anime_mismatch = research`); `review` puts it in the Review queue instead, where the owner keeps or rejects it.
- 2026-11-05 · v0.1.0 ships with movies, TV, downloads through Lantern and TRaSH defaults working end to end, plus requests and the first part of anime, which merged before it. The release hold file is gone, so every merge to main is a release from now on.
- 2026-11-05 · Accounts are made only in Marquee; Jellyfin and Plex follow. Marquee never makes a Jellyfin administrator and never changes an existing one; Marquee admins and the owner see every library.
- 2026-11-05 · Plex can't turn a person off, so an account that is turned off, has Plex access taken away or ends loses its Plex share; turning it on shares again with the same libraries.
- 2026-11-05 · Taking Jellyfin access away turns the Jellyfin user off instead of removing it, so watch history stays; removing the Marquee account removes the Jellyfin user and the Plex share.
- 2026-11-05 · When Marquee doesn't know the password (access given to an existing account, or a linked Jellyfin user), Jellyfin gets a random one until the person next signs in to Marquee, then takes that password. Marquee never stores a plain password.
- 2026-11-05 · Sign-up is by invite only (no open sign-up page), and an invite never makes an admin. Sign-in with Plex or Jellyfin makes an account only when "Plex or Jellyfin sign-in makes an account" is on (off by default), and then leaves that person's server access as it was.
- 2026-11-05 · Mail (SMTP) is in Marquee (`server/src/mail.rs`, lettre) because kit v0.2.1 has none; it is generic and should move to the kit. The mail server `file` writes mails to `<data>/outbox/` for tests.
- 2026-11-05 · "Available" comes from the TMDB ids Jellyfin and Plex report, read every 30 minutes and a minute after each import's scan, kept in `media_available`.
- 2026-11-05 · Password reset links work once for an hour, are kept only as their SHA-256, and the forgot-password answer never says whether an account exists.
- 2026-11-05 · An anime file is checked against the newest request for its series; a series nobody requested with a language choice isn't checked. Dubs are taken to be English, since requests don't ask for the dub's language.
- 2026-11-05 · Anime language choices live in one place, the requests' `request_prefs`; `/api/anime/prefs` reads and writes the same row, and the first release's `anime_prefs` rows are copied there before that table is dropped. Core's AniList client reads the requests' `request_anilist_url`, so there is one AniList setting.
- 2026-11-05 · A release turned down (wrong tracks, or Reject in the Review queue) is remembered by its title and never grabbed again; Lantern is asked to drop it with its files.
- 2026-11-05 · The Android app is the kit v0.2.1 template's (dev.krifmaz.marquee) and talks to Marquee's own API with the kit's phone sign-in (a bearer token per phone), not the Radarr/Sonarr APIs, which need the server's API key that a phone shouldn't hold. Admin actions follow the account's role.
- 2026-11-05 · The Android app is built in its own workflow (`.github/workflows/android.yml`, only when android/ changes) through the kit's kit-android.yml, so the core CI stays as it is; the APK joins releases once the owner adds the four ANDROID_KEYSTORE_* secrets.
- 2026-11-05 · The phone keeps the last answer of each list (calendar week, queue, library) as plain files, shown with its age when the server can't be reached; they are deleted on sign-out and when the server changes, since they belong to one account.
- 2026-11-05 · The Docker image copies a static ffprobe from mwader/static-ffmpeg (a build for each platform), since distroless has no package manager. The sign-in options, the media server scan and ffprobe land in one small PR because each is a line or two of wiring.
- 2026-11-05 · The phone asks for anime without its own language choice: the server uses the account's default (set in the web app), so the request dialog stays one step. A per-request choice can come later.
- 2026-11-05 · Migration reads Radarr's and Sonarr's own API (address + API key) instead of their databases: it works for any version that has API v3, needs no file access to their config, and a dry run is the default. Quality profiles are matched by name, else Marquee's default; existing files are recorded where they are and never moved or renamed.
- 2026-11-05 · A track PR that GitHub reports as cleanly mergeable and that touches none of the files changed on main since its last rebase is merged without another rebase, once green. Every merge to main still runs the full test suite before it is released.
- 2026-11-05 · Invites made on the phone give every library on the servers chosen; picking libraries stays in the web app, so the phone form is three taps. The Plex sign-in opens plex.tv in the phone's browser and asks the server every 2 seconds for up to 5 minutes, since plex.tv can't send the person back to the app.
- 2026-11-05 · jfa-go moves in through its API (users, invites, profiles), never its files. Users are matched by their Jellyfin user, then by name; Jellyfin administrators are left alone. New accounts get a random password and take their Jellyfin password at their first Jellyfin sign-in. An open invite keeps its code and takes the libraries of the Jellyfin user its profile was made from. Nothing is changed on Jellyfin or in jfa-go.
- 2026-11-05 · Moving in from Seerr: an approved Seerr request whose title isn't in Marquee's library comes in as "Didn't work" with the reason, so Retry adds it and starts the search, instead of an approved request nothing looks for. Seerr's admins keep no limits (Marquee's admins have none); a limit Seerr leaves to its global default leaves the account's own as it is.
- 2026-11-05 · A Seerr request already moved in is recognised by title, account, seasons and creation time, so the move can be run again safely.
- 2026-11-05 · The Anime tab reads the existing anime root, `/data/media/anime` (the TRaSH layout in GOALS.md), not `/data/anime` from the request: the anime library is whatever sits in an anime root folder, so a different path is one Folders change away. Anime films are films in an anime root folder or that TMDB calls Japanese animation; requested anime films now go in the anime root (else the movie root).
- 2026-11-05 · The Anime library shows one entry per mapping-list entry of a regular season (a split cour is two entries, each up to where the next starts), named and drawn by AniList; a series the list doesn't know shows one entry per season with TMDB's poster. AniList answers are kept six hours in `anime_anilist` (sooner once a kept next episode has aired) and old ones are shown when AniList is down.
- 2026-11-05 · Discover's studio filter asks AniList for the studio's own anime (AniList can't filter its lists by studio) and narrows them to the list and genre, 20 at a time. Requesting an AniList season asks for that TheTVDB season (from the mapping list); an entry the list can't map to TMDB can't be requested yet and says so.
- 2026-11-05 · The web app had no navigation on phones (the sidebar slid away with nothing to open it), so the Anime PR adds a bottom bar (Movies, TV, Anime, Activity, More; More opens the sidebar) in the app's own `marquee.css`. It is generic and belongs in kit-leptos's shell; move it there with the next kit bump.
- 2026-11-05 · On Android the Anime tab is a sixth bottom-bar tab (Calendar, Requests, Queue, Library, Anime, More), as asked, rather than a third choice in Library; labels stay on one line. Its request dialog now asks the language per request (the account default first), replacing the earlier "phone uses the default" call for requests made from the Anime tab.
- 2026-11-05 · **Port, don't reimagine** replaces "fresh Rust, original apps as reference only": Sonarr, Radarr and Seerr are ported faithfully at commits pinned in `UPSTREAM.lock`, tracked module by module in `docs/PARITY.md`. Earlier calls that differ from upstream (downloads through Lantern only, one shared table for root folders, profiles and qualities, TMDB instead of TheTVDB, roles as Seerr permission bits) still stand until a PR changes them; every other difference is a gap to close.
- 2026-11-05 · Pinned versions are the newest stable releases: Sonarr v4.0.20.3014 (the version the Sonarr contract tests were recorded from), Radarr v6.4.4.10685 (Radarr's `master`; v7.0.x tags are on `develop`, not yet a stable release) and Seerr v3.5.1 (`main`). The Seerr contract tests were recorded from Jellyseerr 2.7.3 and are re-recorded against v3.5.1 by the Seerr port.
- 2026-11-05 · `UPSTREAM.lock` is TOML (one table per app: upstream, fork, tag, commit, license) so Rust, Python and shell (`scripts/parity-fetch.sh`) read it alike. Builds fetch the exact commit, from the Krifmaz fork when it has it, else from upstream: the forks hold the same commits, so nothing waits on the forks existing.
- 2026-11-05 · The forks live in the Krifmaz account as plain GitHub forks (`Krifmaz/Sonarr`, `Krifmaz/Radarr`, `Krifmaz/seerr`), with Marquee's patches (Encore look, base paths) on a `marquee` branch; they are not vendored into this repository, which keeps it small and keeps upstream history and merges simple.
- 2026-11-05 · The API rows of `docs/PARITY.md` are generated by `scripts/parity.py` from the upstream OpenAPI specs and Marquee's routes (Done, Stub = a fixed empty answer, Missing), so they can't drift; the module and UI rows are kept by hand by the PRs that port them.
- 2026-11-05 · Requests are ported from Seerr 3.5.1 (`routes/request.ts`, `MediaRequest.request`, `User.getQuota`) as they are. This replaces the earlier calls that limits skip failed and automatic requests and that an available movie can't be asked for again: like Seerr, every request not declined counts, a movie is blocked only by its oldest request still waiting or approved, and a TV request takes only the seasons not already asked for or there. Permissions are Seerr's bits worked out from Marquee's roles, so an admin passes every check and a can-request account has REQUEST (plus its auto-approve bits).
- 2026-11-05 · Where Marquee's Seerr requests still differ, on purpose: `canRemove` keeps Marquee's meaning (you may remove this request), which the web app and the phone use, until the media module ports `DELETE /media/{id}/file`; Seerr's own page shows that button only to MANAGE_REQUESTS anyway. `filter=declined` stays as Marquee's own filter (Seerr keeps everything for it). Changing a movie request into a TV one (or back) is refused with 400 instead of saving a mix. 4K requests use the one library's availability.
- 2026-11-05 · The forked web apps are built in the image from the pinned commit plus patch scripts in `ui/` (not from patched fork branches): the forks don't exist yet, and scripts that check the upstream text they change fail loudly on a newer release. When the forks exist the same patches can move onto their `marquee` branch.
- 2026-11-05 · Seerr's web app is a static Next.js export at `/requests` (basePath), not Seerr's Node server: the image stays one Rust binary. The few things Seerr's server did for its pages (reading the sign-in and public settings, the movie/TV/collection data) now happen in the browser, and Marquee's server finds `[name]` pages by address the way Next's server does.
- 2026-11-05 · The Encore look in the forked apps maps their colour variables onto the kit's tokens (`tokens.css` is copied in at build time). Seerr's filled indigo buttons use the kit's second accent mixed toward the background, because white text is unreadable on the plain cream/gold accents; these are mixes of kit tokens, not new colours.
- 2026-11-05 · Sonarr and Radarr pages and `initialize.json` (which carries the API key, as upstream) are for admins only; Seerr's pages are for everyone signed in, with roles enforced by the API. Signed-out visitors go to Marquee's sign-in with `?next=`, which only returns to paths on the same server.
- 2026-11-05 · Seerr's "Remove from Radarr/Sonarr" (`DELETE /media/{id}/file`) takes the movie or series out of Marquee's library and marks the title deleted, but leaves the files on disk: Marquee's own Radarr/Sonarr delete doesn't follow `deleteFiles` yet, and deleting people's files waits for that port. `POST /media/{id}/unknown` still hands the status back to the library instead of pinning "unknown", and setting a status pins the whole title (Seerr's per-season `seasons` body is not used), since Marquee works availability out from the library.
- 2026-11-05 · Ported parsers keep the upstream .NET regular expressions character for character and run them through a small bridge (`server/src/parser/net_regex.rs`: repeated group names, pattern whitespace, look-behinds with alternatives of different lengths) on fancy-regex, so a later upstream change can be copied as it is.
- 2026-11-05 · Upstream NUnit `[TestCase]`s are turned into JSON by `scripts/upstream_cases.py` and kept in `server/tests/upstream/<app>/`; the Rust tests check what each upstream test method checks. Regenerate them from the commits in UPSTREAM.lock when the pin moves.
- 2026-11-05 · Until `Parser.cs` is ported, `release.rs` keeps reading titles, seasons and episodes, but its quality comes from the ported QualityParsers: Sonarr's reading for TV and anime, Radarr's for movies (`movie_quality_name`).
- 2026-11-05 · The forked Sonarr and Radarr web apps get upstream's English strings (`server/data/<app>/localization/en.json`, from the pinned commits); other UI languages come when the UI language setting is ported. Radarr's `/localization` keeps its PascalCase `Strings` key, as Radarr sends it. Custom filters live in one table with an `app` column, so each app's list stays its own as upstream.
- 2026-11-05 · Seerr's account routes are ported with Marquee's one-owner model standing in for Seerr's "user 1": the owner can't be removed, only the owner changes the owner or hands out ADMIN, and setting permissions on the owner leaves its role alone. Seerr's permission bits map to Marquee's roles (admin, can request with its auto-approve bits, read-only), so bits Marquee has no role for are dropped. Accounts removed through the Seerr API are removed everywhere, like the Users page (their Jellyfin user and Plex share go too). Renaming an account changes its Marquee sign-in name only.
- 2026-11-05 · The SignalR hub speaks only what the upstream web apps use: negotiate, WebSockets, the JSON hub protocol, pings and `receiveMessage` (no long polling or Server-Sent Events). Its channels are process-wide, one per app; other modules push updates with `signalr::broadcast`, as upstream services call `BroadcastMessage`.
- 2026-11-05 · Sonarr and Radarr API paths (`/<app>/api/`, `/signalr/`, `/feed/`) are folded to lower case before routing, because ASP.NET matches routes in any case and the web apps and other clients send camelCase paths. Only the path is folded, never the query.
- 2026-11-05 · Seerr's discover routes answer in English unless `language` is given, because Marquee has no per-user display language yet (Seerr's `req.locale`). When TMDB fails, the answer is Seerr's own sentence ("Unable to retrieve popular movies.") and what TMDB said goes to the server log. `/discover/watchlist` answers Seerr's empty page for now; Plex watchlist sync is its own port.
- 2026-11-05 · The iCal feeds are written by hand in Ical.Net's shape (RFC 5545 escaping, 75-octet folding, CRLF) instead of pulling in an iCal crate; the properties and their values follow upstream's `CalendarFeedController`. "Today" is the server's local midnight, as `DateTime.Today` is upstream.
- 2026-11-05 · Taking a title off Seerr's blocklist keeps Marquee's record of the title and its requests and only clears the Blocklisted status; Seerr deletes the media row, which would also drop its request history. A title that isn't on the list answers 404 "This title isn't on the blocklist." instead of TypeORM's internal message.
- 2026-11-05 · Languages are two lists (`parser::language::tv`, `movie`) because Sonarr and Radarr give the same language different ids. The subtitle expressions repeat their tag and code groups; .NET keeps every repetition (`Group.Captures`), so the repeated part is captured whole and read again piece by piece, and look-behinds of varying length (`(?<!WEB[-_. ]?)`, `(?<!\d+)`) are rewritten into fixed-length ones in the regex bridge. Two Radarr language cases need `ParseMovieTitle` to take the title out first; they are listed in `tests/languages.rs` and must keep failing until that parser lands.
- 2026-11-05 · Seerr's issues keep Seerr's default permissions: Marquee's requester role maps to Seerr's REQUEST only, so reporting issues is for owners and admins until per-account permissions are stored. An issue or comment that isn't there answers 404 "Issue not found." (Seerr answers 500 with the same words). Issue notifications come with the notifications port.
